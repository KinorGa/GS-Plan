# 从 gcsim 导入伤害轴

[gcsim](https://github.com/genshinsim/gcsim) 是第三方的伤害模拟器。它导出的一次运行里，
`logs` 记着**每一击**：哪一招、什么元素、有没有暴击、打了多少（这份样本是 617 个 `damage` 事件）。
这里做的就是把这些事件翻成本项目伤害轴上的一条条条目，产物和「导出/导入」用的是同一个
`lunaris-config` JSON——所以规划器本来就有入口，不用加界面。

**样本是自足的**：除了伤害日志，`character_details` 里还带着每个队员的等级、命座、天赋等级、
武器和圣遗物**套装**。所以不需要再去读 config.txt——队伍和轴都从这一个文件来。

```bash
npm run gcsim:import                    # 读 scratch/_gcsim_serve_sample.json，写 data/gcsim-config.json
node scripts/gcsim-import.mjs --help    # 见脚本头部：--sample / --out / --abilities / --team / --report
```

产物在规划器右上角「导入」选进去即可。

> 导出文件本身的字段形状（顶层结构、`damage` / `calc` 事件语法、`pre_damage_mods` 这类嵌套状态）
> 记在 [GCSIM-SAMPLE.md](./GCSIM-SAMPLE.md)，改导入器前先看那份，不用再重新反推。

## 为什么需要一张对照表

gcsim 用自己的内部 ability 名（`Azure Devour`、`Sturm und Drang Normal 1`），本地数据里没有这个名字，
对不上就不知道该落到哪个来源的哪一行，只能人工对照，于是有了 `public/data/gcsim-abilities.json`。

- `abilities`：每个角色的每个 ability → `{ source, stage }`。**stage 写中文行名，不写行下标**——
  行名是人能核对的，下标会随着天赋表增删一行整体漂移，而且漂移后不报错、只是悄悄指错行。
- `characters` / `weapons` / `sets`：只写推不出来的特例。gcsim 名基本等于英文名去掉标点再小写
  （`gestofthemightywolf` = "Gest of the Mighty Wolf"），所以角色、武器、套装大多用不着写；
  真正推不出的是别名，例如 gcsim 的 `risingwinds` 其实是「A Day Carved From Rising Winds」。

## 脚本做什么

- 按帧顺序扫描 `damage` 事件，把**连续的同一 ability 合并成一条**，单击数 = 连续次数；
- 这一段的 `critMode` 由它是否**全暴击 / 全不暴击**决定，混在一起就是平均（`avg`）；
- 每条带一个 note，例如 `gcsim：2 击 · 单击 5,955.52 · 合计 11,911.04 · 暴击混合`。
  这个数是 gcsim 真跑出来的，摆在条目里可以直接和旁边的本地面板数对照；
- 一次连续的同名攻击按 `(倍率, 元素)` 分组：只有一组就是普通的一行；多于一组建**多段伤害**父条目，
  每段一个子条目——多段招式因此各段各算，不会全部落在第 0 段上（见下节「倍率」）；
- 队伍全部取自样本的 `character_details`：角色、武器、等级、命座，以及**天赋等级**——注意存的是
  最终等级（把 C3/C5 的 +3 算进去），因为本地存的就是最终值，不这么做会读到错误的一列；
- 命座/天赋的独立伤害（法尔伽 C2、布伦妮 A1/C4 这些）走 `public/data/talent-damage.json`
  那张策展表——它们本来就不在角色的天赋表里，只有那张表才有它们的倍率；
- **面板**：`character_details[i].stats` 就是这次运行喂给 gcsim 的 `add stats` 聚合值，按 gcsim
  自己的 25 位属性顺序排（顺序表见脚本里的 `GS_STAT`，是拿你自己的 `add stats` 行逐格核对过的）。
  每个非零项在圣遗物里写成**一条词条 = 全部总值**，不拆卷数——见下一节为什么；
- **增益**：**逐条**从日志本身来。每个 `damage` 事件都列出**那一击**身上生效的状态
  （`varka-c6-cdmg`、`celestialgift-4pc-*`、`vvpyro`……），带着它当时施加的数值。
  所以一条上挂的卡，就是它自己那几击里出现过的来源，数值也取日志里那一击的数——
  只加到法尔伽身上的自增益，绝不会落到杜林的行上，因为杜林的那几击里没有这个状态。
  卡片的长相（图标、名字、归属）用规划器自己的 `buildUnitSources` 求，不复制一份它的规则；
  归属和数值的对照表在 `public/data/gcsim-abilities.json` 的 `buffs` 里，一栏一栏肉眼可核。
  套装的两半、同一个天赋的两个状态名会并成**同一张卡**（一张卡本来就能带多项）；
  只写了 `reason: conditions not met` 的状态（四风原典、图莱杜拉的回忆）**不挂卡**，
  因为那一击它确实没生效。`pre_damage_mods` / `resist_mods` 这种「名字 + 若干行」的容器会先拆开，
  逐击的 `dmg%` 和减抗的 `amount` 都直接读日志里的数，不再在对照表里写死——杜林那两条减抗的真实值是
  35%，表里那个 20% 才是一直差 0.94 的原因。

## 不做什么（以及为什么）

- **增益不细分到帧。** 日志里每个状态名都带着它当时的数值，所以「谁吃到了」是照抄的，不是猜的；
  但**同一行内的几击不再拆开**（一行里同一状态没有出现过两个不同的值，所以不会有歧义）。
  哪一层在第几帧亮、灭，本地模型没有时序概念，这份导入文件也不假装有。
- **队伍共鸣是一张合成卡。** 火共鸣（`pyro-res`，+25% 攻击力）不属于任何角色或装备，
  本地也还没有「共鸣」这个概念，所以它挂成一张 `other` 类别的卡（名字「火元素共鸣」），
  由 `extraSources` 命名，而不是硬塞给某个角色——那才是猜。
- **圣遗物不做卷数拆分。** `add stats` 是总值，不是五个部位各自的卷。把 128.8% 攻击力拆成一堆
  合法卷会造出一套从没存在过的圣遗物；写成一整条词条，数值一样，但不多说一句假话。
  模型对词条大小本来就没有限制（那个合法值列表是下拉候选，不是校验器），所以这只是展示选择。
- **放不进面板的会说出来。** 向量里 app 没有对应字段的（例如通用 `Dmg%`），或者不在圣遗物曲线上的
  元素值，都不会被悄悄丢掉——`--report` 里逐条列出来。

### 倍率：以 gcsim 自己的数为准

本地天赋表和 gcsim 用的并不总是同一列：法尔伽的 狂飙突进 是表值的 220%，C1 又把 四风将起 翻倍；
一个 stage 还会一次打出好几个不同系数的段。这些不该靠人去解释，所以每一条导入的行（以及每个分段）
都带一个 `scaling = { mult?, hits? }`——这一击 gcsim 真正用的倍率与击数（取自同帧 `calc` 的
`talent`）——字段缺省时才回落到本地表。

只有一处读它：`lib/axis-compute.js` 的 `computePart`。折叠行、展开的卡片和轴汇总都从那里取数
（卡片拿的是同一个 `scaling`，不是自己再查一遍表），所以三处不会各说各话。

一次连续的同名攻击按 `(倍率, 元素)` 分组：多于一组建「多段伤害」父条目 + 每段一个子条目，各自带
`scaling`、元素、逐击的增益卡和暴击模式；父条目的 `summary.parts` 写的就是 gcsim 的这几段，
所以展开一个多段行不会把它塌回一段。

结果：这份样本 457 行，**每行的「合计」都在 gcsim 日志自身数值的 1% 以内**，58 个多段行也不例外。

## 明细（report）

脚本把每个 ability 的映射结果打到 stderr，分四种：`ok` / `忽略(反应)` / `未映射` / `行名过时!`。
末尾还会说清楚**面板**和**增益**各自的结果：词条是不是全部写进了面板（放不进的逐条报出来），
每个来源覆盖了多少条、多少击，以及**没挂上的每一个原因**——表里没有的状态名、读不出的词条、
`reason` 说明没生效的、指向本队不存在来源的，都逐条列出来，不会悄悄少一张卡。

这份样本 617 击的结果：**515 落到行上**，**102 是扩散反应**（`swirl-pyro`，由元素附着触发、
不属于任何角色的天赋行，只能忽略）。**没有未映射的命中。**

## 维护

- **新角色**：gcsim 名推不出本地 id 时脚本会直接报错，并说清在 `characters` 里补哪一条；
- **新 ability**：会出现在「未映射」里，照 `abilities` 的格式补一条即可；
- **行名打错**：会显示「行名过时!」，不会悄悄指到别的行；
- **新增益**：日志里出现了新的状态名时，末尾会打印「状态「X」不在 buffs 表里」。
  查它是哪件武器/哪条命座/哪个套装，在 `buffs` 里补一条 `"gcsim 状态名": "本地来源键"` 即可；
  日志会给出数值（`atk%: 0.25`、`cd: 0.80`、`dmg%: 0.22`、`amount: -0.35`），照着写的值来自日志本身，
  不用抄说明；真要写死一个常数，才用 `{ "source": "...", "stats": { "本地字段": 数值 } }`；
- **换了导出文件**：`--sample` 指过去就行，什么都不用改。
