# 从 gcsim 导入伤害轴

[gcsim](https://github.com/genshinsim/gcsim) 是第三方的伤害模拟器。它导出的一次运行里，
`logs` 记着**每一击**：哪一招、什么元素、有没有暴击、打了多少（这份样本是 625 个 `damage` 事件）。
这里做的就是把这些事件翻成本项目伤害轴上的一条条条目，产物和「导出/导入」用的是同一个
`lunaris-config` JSON——所以规划器本来就有入口，不用加界面。

**样本是自足的**：除了伤害日志，`character_details` 里还带着每个队员的等级、命座、天赋等级、
武器和圣遗物**套装**。所以不需要再去读 config.txt——队伍和轴都从这一个文件来。

```bash
npm run gcsim:import                    # 读 scratch/_gcsim_serve_sample.json，写 data/gcsim-config.json
node scripts/gcsim-import.mjs --help    # 见脚本头部：--sample / --out / --abilities / --team / --report
```

产物在规划器右上角「导入」选进去即可。产物是**池化后**的 `lunaris-config`：重复的来源/增益只在文件顶部
存一份，行里留索引——这份 400 行的样本因此从 6.27 MB 缩到 1.44 MB，仍然是给人看的 pretty JSON。
规则见 [DEV.md](./DEV.md) 的 `axes-pool.js`。

**不经过命令行也行。** 规划器右上角「导入」旁边多了模式选择，切到 `gcsim` 后直接选
`serve_sample.json.gz`，确认框会先报「映射了多少击 / 有多少没映射」。页面优先把原始字节 POST 给
C# 的 `/api/gcsim/import`（与 `GsPlan.Core` 的导入器共用同一份数据目录）；纯 Node 开发服务器或接口不可用时，
`src/lib/gcsim-client.js` 会退回 `src/lib/gcsim-import.js`，`scripts/gcsim-import.mjs` 则是同一份 JS 实现的命令行薄壳。
C# 是它的移植版，`tests/check-csharp-gcsim.mjs` 对 `doc` / `report` 逐字段对拍；两条路产出的文件是同一份。

> 注意页面跑的是 `dist/` 的**打包产物**，不是 `src/`：改了 `src/` 或 `public/data/` 之后先
> `node build.mjs` 再看页面，否则浏览器里还是修复前的旧代码——修好了导入却在页面上看到旧值，
> 十有八九是这里。

> 导出文件本身的字段形状（顶层结构、`damage` / `calc` 事件语法、`pre_damage_mods` 这类嵌套状态）
> 记在 [GCSIM-SAMPLE.md](./GCSIM-SAMPLE.md)，改导入器前先看那份，不用再重新反推。

## 为什么需要一张对照表

gcsim 用自己的内部 ability 名（`Azure Devour`、`Sturm und Drang Normal 1`），本地数据里没有这个名字，
对不上就不知道该落到哪个来源的哪一行，只能人工对照，于是有了 `public/data/gcsim-abilities.json`。

- `abilities`：每个角色的每个 ability → `{ source, stage }`。**stage 写中文行名，不写行下标**——
  行名是人能核对的，下标会随着天赋表增删一行整体漂移，而且漂移后不报错、只是悄悄指错行。
- `characters` / `weapons` / `sets`：只写推不出来的特例。gcsim 名基本等于英文名去掉标点再小写
  （`gestofthemightywolf` = "Gest of the Mighty Wolf"），所以角色、武器、套装大多用不着写；
  真正推不出的是别名，例如 gcsim 的 `risingwinds` 其实是「A Day Carved From Rising Winds」。

## 脚本做什么

- 按帧顺序扫描 `damage` 事件，把**同一次施放合并成一条**。判定用的是 gcsim 自己写的事件字段
  `logs.source_frame`——那一击所属施放的起始帧。同一 ability、同一 `source_frame` 的命中都属于
  同一次施放，**哪怕中间夹了别的技能**（杜林的大招三段落在同一帧，日志里却被别的命中隔开，
  旧的「相邻才算一次」规则会把它切成 2+1，行里就只显示两段）；
- 这一段的 `critMode` 由它是否**全暴击 / 全不暴击**决定，混在一起就是平均（`avg`）；
- 每条带一个 note，例如 `gcsim：2 击 · 单击 5,955.52 · 合计 11,911.04 · 暴击混合`。
  这个数是 gcsim 真跑出来的，摆在条目里可以直接和旁边的本地面板数对照；
- 一次施放内部**每一击各成一段**：只有一击就是普通的一行；多于一击就建**多段伤害**父条目，
  每击一个子条目——多段招式因此各段各算，不会全部落在第 0 段上（见下节「倍率」）。
  曾经把「倍率/元素/暴击/增益数值都相同」的几击并成一段（行里画成 `×2`），但那在一击触发反应、
  或状态在两击之间移动时只能报出两者的平均——那不是日志里的任何一个数；
- 队伍全部取自样本的 `character_details`：角色、武器、等级、命座，以及**天赋等级**——注意存的是
  最终等级（把 C3/C5 的 +3 算进去），因为本地存的就是最终值，不这么做会读到错误的一列；
- 命座/天赋的独立伤害（法尔伽 C2、布伦妮 A1/C4 这些）走 `public/data/talent-damage.json`
  那张策展表——它们本来就不在角色的天赋表里，只有那张表才有它们的倍率；
- **面板**：`character_details[i].stats` 就是这次运行喂给 gcsim 的 `add stats` 聚合值，按 gcsim
  自己的 25 位属性顺序排（顺序表见脚本里的 `GS_STAT`，是拿你自己的 `add stats` 行逐格核对过的）。
  每个非零项在圣遗物里写成**一条词条 = 全部总值**，不拆卷数——见下一节为什么；
- **增益**：**逐条**从日志本身来。每个 `damage` 事件都列出**那一击**身上生效的状态
  （`varka-c6-cdmg`、`celestialgift-4pc-*`、`vvpyro`……），带着它当时施加的数值。
  所以一条上挂的卡，就是它自己那几击里出现过的来源，数值也取日志里那一击的数——
  只加到法尔伽身上的自增益，绝不会落到杜林的行上，因为杜林的那几击里没有这个状态。
  卡片的长相（图标、名字、归属）用规划器自己的 `buildUnitSources` 求，不复制一份它的规则；
  归属和数值的对照表在 `public/data/gcsim-abilities.json` 的 `buffs` 里，一栏一栏肉眼可核。
  套装的两半、同一个天赋的两个状态名会并成**同一张卡**（一张卡本来就能带多项）；
  只写了 `reason: conditions not met` 的状态（四风原典、图莱杜拉的回忆）**不挂卡**，
  因为那一击它确实没生效。`pre_damage_mods` / `resist_mods` / `def_mods` 这种「名字 + 若干行」
  的容器会先拆开，逐击的 `dmg%`、减抗减防的 `amount` 都直接读日志里的数，不再在对照表里写死——
  杜林那两条减抗的真实值是 35%，表里那个 20% 才是一直差 0.94 的原因。
  还有两笔钱任何状态名都不会提（`flat_dmg` / `ignore_def`），它们走 calc 事件——
  见下面「calc 独有的两个因子」。

## 不做什么（以及为什么）

- **增益不细分到帧。** 日志里每个状态名都带着它当时的数值，所以「谁吃到了」是照抄的，不是猜的；
  但**每一击都是自己的一段**：同一次施放里的每一击都拆成一个独立子条目（一段 = 一击），哪怕两击数值一模一样。
  合并成 `×2` 试过，但一击触发反应、或状态在两击之间移动时，合并只能报出两者的平均——那不是日志里的任何一个数。
  哪一层在第几帧亮、灭，本地模型没有时序概念，这份导入文件也不假装有。
- **队伍共鸣是一张合成卡。** 火共鸣（`pyro-res`，+25% 攻击力）不属于任何角色或装备，
  本地也还没有「共鸣」这个概念，所以它挂成一张 `other` 类别的卡（名字「火元素共鸣」），
  由 `extraSources` 命名，而不是硬塞给某个角色——那才是猜。
- **圣遗物不做卷数拆分。** `add stats` 是总值，不是五个部位各自的卷。把 128.8% 攻击力拆成一堆
  合法卷会造出一套从没存在过的圣遗物；写成一整条词条，数值一样，但不多说一句假话。
  模型对词条大小本来就没有限制（那个合法值列表是下拉候选，不是校验器），所以这只是展示选择。
- **放不进面板的会说出来。** 向量里 app 没有对应字段的（例如通用 `Dmg%`），或者不在圣遗物曲线上的
  元素值，都不会被悄悄丢掉——`--report` 里逐条列出来。

### 倍率：以 gcsim 自己的数为准

本地天赋表和 gcsim 用的并不总是同一列：法尔伽的 狂飙突进 是表值的 220%，C1 又把 四风将起 翻倍；
一个 stage 还会一次打出好几个不同系数的段。这些不该靠人去解释，所以每一条导入的行（以及每个分段）
都带一个 `scaling = { mult?, hits? }`——这一击 gcsim 真正用的倍率与击数（取自同帧 `calc` 的
`talent`）——字段缺省时才回落到本地表。

只有一处读它：`lib/axis-compute.js` 的 `computePart`。折叠行、展开的卡片和轴汇总都从那里取数
（卡片拿的是同一个 `scaling`，不是自己再查一遍表），所以三处不会各说各话。

一次施放内部的**每一击都是一段**（不再按 `(倍率, 元素, 暴击结果, 增益数值)` 把相同的几击并成一段）：
多于一击就建「多段伤害」父条目 + 每击一个子条目，各自带 `scaling`、元素、逐击的增益卡和暴击模式；
父条目的 `summary.parts` 写的就是 gcsim 的这几击，所以展开一个多段行不会把它塌回一段。

结果：这份样本 411 行，**每行的「合计」都在 gcsim 日志自身数值的 0.2% 以内**，多段行也不例外。

### calc 独有的两个因子：附加伤害值与无视防御

有一类增益 damage 事件的状态列表**永远看不到**：尼可 C4 的附加伤害、杜林 C1 的附加伤害、
尼可 p4 给奥迹造影的附加伤害、尼可 C6 和杜林 C6 的无视防御。它们只写在同帧 `calc` 事件的
`flat_dmg` / `ignore_def` 字段里（字段语义和公式链见 [GCSIM-SAMPLE.md](./GCSIM-SAMPLE.md)）。
这两个因子曾经全部丢失——`flat_dmg` 在本地模型里根本没有字段，`ignore_def` 有字段却没人
挂卡——每行只剩 gcsim 实际值的 42%~53%，而且是系统地少，不是四舍五入。

现在的处理：

- **伤害模型多了 `flatDmg` 字段**：`攻击力 × 倍率 + 附加伤害值`，再进增伤区——和 gcsim
  的算式逐项一致。面板、增益卡词条、卡片表头都有它（增益卡上可以手动填，和别的字段一样）；
- **导入器把每击的 `flat_dmg` 拆回来源卡**，规则写在对照表新增的 `calc` 段。难点是
  「这一击身上有没有这个源」日志不写：尼可 C4 对**每个角色各自**随她的爆发周期开关，
  同一轮里法尔伽有 C4+C1、仅 C1、仅 C4 三种命中。所以拆法是**从总数反推**——试所有来源
  组合，能复现日志 `flat_dmg` 的组合就是答案。候选值的来法写在规则里：`observedBy` 表示
  该源的量可以从某个角色自己的命中观察到（杜林吃不到自己的 C1，他自己的 `flat_dmg` 恒等于
  尼可 C4 的量）；`of` + `factor` 表示该源 = factor × of 角色的实时攻击力（读他自己的 calc）。
  每条规则取自己的候选值，最后一条拿剩余，**各卡之和恒等于日志总数**——拆分只决定归属，
  永远不会改数。拆不出来就整笔挂第一条规则，并在报告里说「拆不成 calc 表里的来源」，不猜；
- **`ignore_def` 按份额组合拆**：0.4 = 尼可 C6（全队），0.3 = 杜林 C6（`forChar` 限定只给
  他自己的命中，避免把他自己的 0.3 错挂到尼可卡上），0.7 = 两张都在。于是杜林 C6 的卡上
  同时挂着 减防30（`def_mods` 来的敌方 debuff）和 无视防御30（calc 来的他自己）——
  两个因子，一张卡，和命座描述一致。

## 明细（report）

脚本把每个 ability 的映射结果打到 stderr，分四种：`ok` / `忽略(反应)` / `未映射` / `行名过时!`。
末尾还会说清楚**面板**和**增益**各自的结果：词条是不是全部写进了面板（放不进的逐条报出来），
每个来源覆盖了多少条、多少击，以及**没挂上的每一个原因**——表里没有的状态名、读不出的词条、
`reason` 说明没生效的、指向本队不存在来源的，都逐条列出来，不会悄悄少一张卡。

这份样本 625 击的结果：**525 落到行上**，**100 是扩散反应**（`swirl-pyro`，由元素附着触发、
不属于任何角色的天赋行，只能忽略）。**没有未映射的命中。**

## 代码在哪

- `src/lib/gcsim-import.js` — **导入器本体**，纯函数：日志、对照表、目录、角色详情、天赋表全部是参数。
  两种调用方（命令行 / 页面）共用它，所以不存在第二份会漂移的实现；`tests/check-gcsim-import.mjs` 也用同一份。
- `src/lib/gcsim-sample.js` — 页面侧接线：认 magic bytes 解压 gz/zlib、拉数据集、调上面的函数。
- `scripts/gcsim-import.mjs` — 命令行侧接线：读盘、写盘，其余都在上面那个模块里。

## 对照表是生成的

`public/data/gcsim-abilities.json` 的 `abilities` 不再手写，由 `scripts/gcsim-map.mjs`
从 gcsim 的 Go 源码生成：

```
npm run gcsim:map            # 只打印覆盖率
node scripts/gcsim-map.mjs --report   # 再列出所有没配上的 ability
node scripts/gcsim-map.mjs --write    # 写回 gcsim-abilities.json
```

它从每个 `info.AttackInfo{...}`（以及散在文件里的 `ai.Abil = "..."`）里读出 ability 名，
用「名字属于哪个文件」定来源，再拿名字去对本地 `public/data/char/en/<id>.json` 的英文行名——
英文行和中文行**逐行对齐**（生成器自己断言这件事），所以对上英文行就等于对上中文 `stage`。

`characters` 只写推断不出的别名，来源是 gcsim 自己的 `pkg/shortcut` 表；`weapons` / `sets`
目前都能按英文名推断，是空的。

**不猜。** 配不上的 ability 宁可不写（导入时会出现在报告里），也不写一个像是对的错行；
旅行者按元素分文件，暂不生成。当前 113 个角色里 112 个有表，约 90% 的 ability 落到行上。

## 维护

- **新角色**：gcsim 名推不出本地 id 时脚本会直接报错，并说清在 `characters` 里补哪一条；
- **新 ability**：会出现在「未映射」里，照 `abilities` 的格式补一条即可。
  但 `abilities` 是**生成**的，手塞的那条下一次 `--write` 就没了——改完要重跑
  `node scripts/gcsim-map.mjs --write`，或者走下面的 `teamAbilities`；
- **出现在全队日志里的协同攻击**：走 `teamAbilities`，**不要**按角色往 `abilities` 里塞。
  尼可 C1 的协同攻击 `Arcane Projection: Unity` 由**当前场上角色**打出——用他的元素、
  他的攻击力，并「视为由该角色造成的伤害」，所以日志里它挂在四个人各自的 `char_index`
  下，而它的名字对不上任何人的天赋行。表里写 `source: "flatdmg"`，导入器按**这一击
  自己的元素**解析成对应元素/物理的「附伤」行（`src/char-sources.js` 的
  `flatDamageSources`：7 元素 + 物理，每个角色都自带）。
  **以前**这条是按角色塞进 `abilities`、指到各自的元素爆发上的：法尔伽那一轮从没放过
  爆发，统计数据里却凭空多出 7.1% 的「元素爆发·我即朔风」，就是 14 击协同攻击被挂错
  了行；
- **新的附加伤害 / 无视防御来源**：报告会打「拆不成 calc 表里的来源」。查清它是谁的命座/
  天赋、量怎么算，在对照表的 `calc` 段补一条规则即可（三种形状：`ability` 独占、
  `observedBy` 观察、`of`+`factor` 折算；格式见该段自带的 `_comment`）；
- **行名打错**：会显示「行名过时!」，不会悄悄指到别的行；
- **新增益**：日志里出现了新的状态名时，末尾会打印「状态「X」不在 buffs 表里」。
  查它是哪件武器/哪条命座/哪个套装，在 `buffs` 里补一条 `"gcsim 状态名": "本地来源键"` 即可；
  日志会给出数值（`atk%: 0.25`、`cd: 0.80`、`dmg%: 0.22`、`amount: -0.35`），照着写的值来自日志本身，
  不用抄说明；真要写死一个常数，才用 `{ "source": "...", "stats": { "本地字段": 数值 } }`；
- **换了导出文件**：`--sample` 指过去就行，什么都不用改。

测试：`tests/check-gcsim-import.mjs`（用一份两击的合成样本跑全部分支，不依赖 5 MB 的导出文件）。
