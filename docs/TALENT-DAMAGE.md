# 天赋 / 命座 伤害源（审核与维护）

> 一句话：**哪些命座和天赋算「一次独立伤害」，是人工审核过的，存在
> `public/data/talent-damage.json` 里；运行时只读它，不猜。**

## 为什么不能自动判定

伤害源的菜单原本只有普通攻击 / 元素战技 / 元素爆发三行。但命座和天赋也会直接造成
伤害 —— 法尔伽二命「进行一次额外攻击，造成 800% 攻击力的风元素范围伤害」就是一例，
没有这一行，围绕它排的轴根本表达不出来。

问题在于**数据集没有说哪条命座是伤害**。三条看起来可行的路，实测都不行：

| 来源 | 结果 |
|---|---|
| `params[0] * 100` | 即使只看「文本明确说了倍率」的那批，也只有约 **60%** 正确；错的时候差 5 倍以上 |
| `attacks` 字段 | 32 个角色有命座条目，但 **105 条里 0 条**的 `damageParam` 是数字，全是 `Klee_Constellation_4_Damage` 这种符号；法尔伽根本没有条目 |
| 运行时读描述文本 | 好得多（约 93%），但仍会把「伤害提高」当成「造成伤害」 |

`params[0]` 的具体反例（都是实测，不是推测）：

| 角色 | `params[0]` | 描述实际说的是 | 文本里的真值 |
|---|---|---|---|
| 可莉 C4 | `1` | 造成 **555%** 攻击力的火元素伤害 | 555 |
| 香菱 C2 | `2` | 造成 **75%** 攻击力的火元素伤害 | 75（在 `params[2]`）|
| 神里绫华 C6 | `10` | 每过 **10 秒**…伤害提高 298% | 298 |
| 温迪 C2 | `0.25` | 抗性降低 **24%** | 24（而且 0.25 ≠ 0.24）|
| 旅行者 C1 | `5` | 恢复 **5 点**元素能量 | — |
| 雷泽 C6 | `0.1` | 造成 **100%** 攻击力的雷元素伤害 | 100 |

`params` 的下标也不稳定：香菱的真值在 `params[2]`，旅行者「异邦的*」系列在
`params[7]`。

**所以：离线判定一次 → 存成文件 → 人工审核 → 运行时只读。**

## 文件格式

`public/data/talent-damage.json`

```jsonc
{
  "_note": "...",           // 说明：这是人工审核的产物
  "_schema": 1,
  "_fields": { ... },       // 每个字段的含义，自解释
  "characters": {
    "10000128": {                        // 角色 id = 文件名
      "const2": {
        "kind": "constellation",
        "damage": true,                  // ← 唯一决定「是否出现在菜单里」的字段
        "mult": 8,                       // 小数：8 = 800%
        "basis": "攻击力",                // 倍率基于什么
        "element": "Anemo",              // null = 跟随角色自身元素
        "hits": 1,
        "verified": false,               // 人工确认后置 true
        "needsReview": false,            // true = 提取不到明确倍率，需要人工
        "name": "「待天光破晓，我们便要踏上征途」",
        "text": "施放特殊元素战技四风将起时…"   // 原文，审核时不用再翻别处
      }
    }
  }
}
```

**契约（很重要）：**

- `damage: true` → 出现在攻击段菜单里
- `damage: false` → **不出现**（保留在文件里，标注「审过了，不是伤害源」）
- `damage: true` 但 `mult` 为空/≤0 → **不出现**（半成品，不猜）
- 文件里没有这个角色 / 这一条 → **不出现**
- 文件读不到 → 三行主动技能照常工作，只是没有命座行（**降级，不崩**）

`element` 用**首字母大写**（`Anemo` / `Physical`），跟 `source.element` 的既有写法一致。
`DAMAGE_TYPES` 是小写的，那是面板字段（`anemoDmg`）的键，别混用。

## 怎么改

### 方式一：审核页面（推荐，批量）

从**配队规划页右上角**点「伤害源审核」，或直接开：

```
http://127.0.0.1:5199/audit.html
```

- **列出数据集中全部 1365 条**（每个角色的每个命座 + 每个天赋槽），一条不漏
- 每行有**角色头像 + 命座/天赋图标 + 元素图标**，一眼能认出在审什么
- 勾选「是伤害源」、填倍率（按百分数，800 就是 800）、选元素
- 可按角色筛选、按状态筛选、搜索名称或描述
- 点「导出 talent-damage.json」，**用它覆盖 `public/data/talent-damage.json`**，重新构建

**为什么是全量的：** 审核过的清单必须**完整**才可信。第一版只收录"看起来像伤害"的
条目，1365 条里只写了 326 条 —— 剩下 1039 条是**缺失**，而缺失和"审过了、不是"
在文件里长得一模一样。你没办法确认一个你看不到的判定，也没办法把脚本判错的那条打开。
所以现在每一条都有明确结论和理由。

排序把**已启用**放最前，其次**待人工审**，最后是已判定非伤害的 —— 需要你注意的不会被
淹没。每条展开（▼）能看到**原始描述**和**判定依据**。

### 方式二：直接改 JSON

格式见上，字段自解释。适合少量修改。

### 方式三：重新生成草稿

```bash
node scripts/audit-talent-damage.mjs          # 只启用「倍率明确」的
node scripts/audit-talent-damage.mjs --all    # 放宽（不推荐）
```

**注意：这会覆盖你的审核结果。** 生成脚本是**起草**工具，不是权威。

## 生成脚本的判定规则

保守，只认同时满足的：

1. 某个**分句**里出现 `造成…伤害` 或 `额外攻击`
2. 该分句的动词是「造成」而不是「提高 / 提升 / 加成」
3. 该分句里的百分比**紧贴** `攻击力 / 生命值上限 / 防御力 / 元素精通`

**按分句**判断是关键：整段正则会把「获得 10% 风元素伤害加成」里的 10% 和三句之外的
「造成原本 140% 的伤害」配成一对。实测这一条修掉了 16 个误判。

也排除 `造成原本X%的伤害`（这是对**已有**伤害的倍率，属于增益，不是新伤害源）。

## 当前状态

- **全部 138 个角色的 1365 条**命座/天赋槽都在文件里，一条不漏
- 其中 **326 条**看起来像伤害实例（`candidate: true`）
- **79 条** `damage: true`（倍率明确，已启用）
- **247 条** `needsReview: true`（像伤害但提取不到明确倍率，等你审）

其余是脚本已判定**不是**伤害的（`reason` 写明依据：`damage bonus, not a hit` /
`talent level-up, not a hit` / `duration/cooldown` 等）。审核时**先看 `reason`**，
大多数可以快速确认。

另有一批 `reason: "empty slot in the dataset (no such passive)"` —— 那是数据集里
字面量为 `""` 的占位槽（没有第四个天赋的角色），也记录下来，这样"缺失"永远是
有解释的。
